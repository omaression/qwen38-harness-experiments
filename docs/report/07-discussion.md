# VI. Discussion and Threats to Validity

## A. Synthesizing gate verdicts, noise floors, and capability decomposition

Across all four experiments, two structural lessons govern automated LLM regression gating. First, **ceiling and small-sample suites confuse serving jitter with capability loss**. In Experiment A and Experiment C's C0 control, temperature-0 bfloat16 reruns shift 1–3 items per split ($\pm 0.041$ interval on 74 items), causing a strict margin-0 gate to reject an identity LoRA and identical reruns. Meanwhile, ceiling compression (1.000 baselines on `demo` and near-1.000 baselines on `humanevalfix`) prevents positive discrimination and hides real degradation—such as Ternary Bonsai 2's extra truncation and syntax losses staying inside the noise band. Conversely, non-ceiling real-repository suites (`swe_review_bench`, $n=400$; `swe_coder_effort`, $n=297$) drive $\mathrm{MDE}_{80}$ well below real effect sizes and achieve sharp statistical separation ($p < 10^{-12}$).

Second, **format recovery and reasoning discrimination must be separated explicitly**. Pre-specified `noninferior/1` gates intentionally penalize malformed JSON and excessive reasoning because production callers receive raw replies. Yet post-hoc `both_valid_compare` and capped-base controls reveal three radically distinct regimes: (1) in Experiment B, `w700` SFT improves *both* formatting ($0.810 \to 1.000$) and conditional judgment ($+0.089$, $p=6.17\times 10^{-4}$); (2) in the security confound, SFT improves formatting while actually harming conditional classification ($-0.040$ vs. capped base); and (3) in Experiment D, reducing coder effort to `medium` eliminates truncation ($119 \to 0$) and lifts usable patches $+0.391$ held-out ($+0.448$ pooled), yet still fails `think_validity` (0.521 < 0.90) without SFT length calibration.

## B. Internal validity

**Serving nondeterminism and single-sample recording.** Every arm stores one completion per item at temperature 0 (or 0.1 in Experiment D). Batching, LoRA kernels, and speculative decoding alter floating-point reduction orders [14], [15], as measured by C0 (8 discordant items of 345 across HumanEvalFix). Notice that C0 measures the vLLM bf16 noise floor; `llama.cpp` arms lacked a dedicated rerun, leaving Q8_0/Q2_0 rerun variance unmeasured. Furthermore, C1 (`q8-llamacpp` vs. `bf16-vllm`) mixes engine differences with 8-bit quantization, and Ternary Bonsai 2 [31] is evaluated at greedy temperature 0 rather than its publisher's recommended stochastic sampling regime.

## C. External validity

While `demo` and `humanevalfix` cover only single-function Python repairs, `swe_review_bench` (12 external repos) and `swe_coder_effort` (65 repos) evaluate realistic multi-file repository workflows. However, real execution in containers remains outside the lightweight `python -I -S` sandbox of CI replay; thus Experiment D's `patch` feature validates applicability, syntax, and SAST cleanliness while relying on the paired 5-agent rollout study ($n=50$) for end-to-end containerized test resolution.

## D. Construct validity

**Confounded primary metrics and proxy signals.** Uncapped base failures on `swe_review_bench` (55 length truncations) and `swe_coder_effort` (119 truncations) dominate raw end-to-end deltas; readers must examine `both_valid_compare` and failure breakdowns before attributing usability swings solely to reasoning ability. Conversely, `gold_match_rate` (0.012–0.018 in Experiment D) underestimates semantic equivalence among alternative valid patches. In SAST, static aliasing handles direct and chained references cleanly, while `swe_coder_effort` validation dropped 3 of 300 tasks whose reference diffs already contained `pickle`/`marshal` or `interpreter-tamper` constructs. Notice also that newly un-truncated `effort-medium` patches exposed 1 additional `eval-exec` violation simply because truncated `xhigh` replies never emitted a parseable diff on that item. Finally, `humanevalfix`'s wrong patches wrap buggy code behind explicit input guards, making TNR near 1.000 artificially easy compared to `swe_review_bench`.

## E. Conclusion validity

**Power, cluster bootstrap vs. McNemar, and post-hoc clarity.** On small suites ($n=13\text{--}74$), percentile bootstrap intervals with few discordant clusters can exclude zero even when exact McNemar does not reach $p < 0.05$ (e.g., Experiment A dev judge: CI [+0.038, +0.269] vs. $p=0.125$). Reporting both alongside $\mathrm{MDE}_{80}$ prevents misinterpretation. Similarly, scaling to $n=169\text{--}400$ clustered items resolves both type I and type II ambiguity. While H1–H2 stem from specification and H3–H8 follow each arm's construction, we explicitly separate pre-specified `noninferior/1` gate outputs from post-hoc `both_valid_compare`, error breakdowns, and margin 0.05 sensitivity readings. Public benchmarks (`demo`, `humanevalfix`) protect against prompt overfitting rather than internet pretraining contamination [19], [20].
