## F. Agentic Harness Feature Ablations and Confound Synthesis

The table below (matching `docs/paper/figures/fig-ablations.pdf`) synthesizes three architectural ablations bridging single-turn evaluation with closed-loop agentic deployment.

| Study | Arms compared | $n$ | Metric | Baseline | Candidate | Finding / $\Delta$ [$p$-value] |
|---|---|---|---|---|---|---|
| Budget-forcing confound | `sec-lora` vs. uncapped base | 396 | BA | 0.551 | 0.599* | $\Delta=+0.048$ ($p=0.032$); schema $0.838 \to 0.992$ |
| Budget-forcing confound | `sec-lora` vs. capped base | 396 | BA | 0.639 | 0.599* | $\Delta=-0.040$ ($p=0.023$, CI [-0.076, -0.011]) |
| Test context + replan | MBPP + context + replan vs. v1 | 299 / 814 | 1st-try pass | 9.5% | 88.0%† | `NameError` $93.0\% \to 0\%$; 10.1% overfit caught |
| Acceptance gate | `tests+SAST` + cap vs. veto | 50 | Resolved rate | 60% (30/50) | 68% (34/50) | 34.8% false-rej. gone; 100% think; 91.5k$\to$13.1k tok |

*\*Exact security LoRA BA is 0.598485 (0.598 to even-round 3 d.p., 0.599 consistent with $0.551+0.048$ and $0.639-0.040$). †Post-exclusion $n=295$: 88.5%.*

**Budget-forcing baseline confound.** On $n=396$ repository-disjoint security classification items (128 repo clusters), comparing an SFT security LoRA against uncapped `qwen38-base` (0.551 BA, schema 0.838, think 0.235) creates an illusory $+0.048$ gain ($p=0.032$, schema 0.992). However, comparing the exact same adapter against a paragraph-capped base control (0.639 BA, schema 1.000, think 1.000) uncovers a genuine $-0.040$ capability regression (95% CI [-0.076, -0.011], $p=0.023$; $-0.036$, $p=0.044$ on $n=393$ mutually valid items). Format repair alone must therefore never be mistaken for capability gain.

**Test visibility and plan revision.** Supplying read-only failing/shown test context plus failure-triggered replanning in multi-agent MBPP rollouts lifts first-attempt verification from 9.5% ($n=814$) to 88.0% ($263/299$; $261/295=88.5\%$ post twin-exclusion), completely eliminating `NameError` first-attempt failures (93.1% of 722 MBPP failures, 93.0% overall $\to 0/33$). Crucially, withholding hidden tests catches 10.1% ($35/347$) shown-test overfitting.

**Deterministic `tests+SAST` gating vs. LLM auditor veto.** Across $n=50$ paired real-repository 5-agent rollouts, gating acceptance on LLM review/security/judge vetoes false-rejects 34.8% ($16/46$) of test-verified patches (and 15.0% [45/299], or 15.1% [47/312] post-exclusion, on MBPP, largely from spurious CWE-400 alarms while auditors sit near chance, 0.49–0.57 BA, against hidden tests). Replacing auditor veto with deterministic `tests+SAST` (`audit=on_reject`) plus thinking-window calibration resolves 34/50 (68%) vs. 30/50 (60%) with 0 false accepts, raises think-window compliance from 38.0% (0.3802) to 100% (1.000), and reduces tokens per resolved task $7.0\times$ (91,473 $\to$ 13,090).
